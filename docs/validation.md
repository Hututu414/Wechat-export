- 只读复制 DB/WAL，双轮哈希验证稳定性，认证每一页及 WAL checksum/salt，仅合并最后提交前的有效帧；副本通过 SQLite quick_check。
- 最后一次完整复测读取 646 个会话，其中 498 个有消息，392,468 条去重后消息；SQL COUNT 和流式读取数量相同，canonical ID 无重复，各会话时间有序。运行中的微信仍会自行接收新消息，因此不同时点总量有所变化。
- 文本 260,382；图片 23,316；语音 2,756；视频 738；文件 1,218；引用 10,735；位置 72；链接 58,518；表情 17,671；系统 6,328；unknown 10,734。unknown 保留原始字段，不等于漏掉的消息。
- 发送者来自**各消息分片自己的 `Name2Id.rowid`**。不能把 `message_resource.SenderName2Id` 的编号用于消息表：针对一个真实分片的 52,672 条私聊文本，该库本地映射全部匹配自己/对方，资源库全局映射全部不匹配。该问题已修正，并增加两个分片使用不同编号的回归数据。
- 最终复测 `is_self=true` 为 60,766 条；文本及已识别媒体均能解析发送者。5,954 条系统或 unknown 记录无法确定发送者，输出 null 和警告。群成员 ID 使用相应分片映射，昵称优先联系人备注/昵称，不宣称已恢复历史群昵称。

## 性能（生成数据，不冒充真实聊天）

Release 可执行文件，两个会话、两个分片，逐行生成 fixture。`scripts/measure.ps1` 顺序执行，通过 Windows 进程峰值工作集计数采样；不含 GUI、Key 扫描或真实数据库复制。

| 去重后消息数 | JSONL 字节数 | 导出耗时（含 COUNT） | 整个基准耗时 | 峰值工作集 |
| ---: | ---: | ---: | ---: | ---: |
| 100,002 | 29,753,383 | 0.352 s | 0.629 s | 14.79 MiB |
| 1,000,002 | 298,528,387 | 3.939 s | 4.815 s | 18.30 MiB |

该结果证明此合成场景没有全量消息 Vec 导致的线性内存增长，不是所有消息体长度和磁盘上的吞吐承诺。UI 的 OpenGL/字体固定开销另计，启动时观察约 191 MiB 工作集。

## 发行与边界

- release EXE 为 Windows GUI / PE x64；资源表包含图标、版本信息。静态 CRT，PE 导入仅 Windows 系统 DLL；未导入 WCDB、Python、Node、WebView 或额外 MSVC runtime DLL。
- 产品源码未使用网络 API；没有 WS2_32 / WinHTTP 导入。开发阶段曾访问公开源码和使用 imagegen 制作图标，均未提供本机聊天数据。
- 没有对运行中微信文件做“哈希永远不变”的错误承诺。源文件访问权限和所有写路径已审查；未暂停微信做隔离哈希实验，也未修改原库权限以测试。
- 尚未覆盖：其他 4.x 版本、无 OpenGL 驱动的干净虚拟机、多账号同时登录、物理磁盘耗尽、断电恢复、所有 XML 子类型/历史群昵称。错误保持显式，不将未测项目写为通过。
- 最终保留程序、源码、图标和不含聊天内容的文档；测试 JSON/JSONL、解密副本、合成库及截图已清除，测试 GUI 已正常退出。发行压缩包检查未发现聊天数据文件。
